# 前端界面与展示配置概览

最近评估日期：2026-07-13

本文档维护当前前端界面布局、已实现功能，以及可以安全手工调整的纯前端展示配置。后续如果前端导航、页面布局、模块可见性、默认展示数量、分页方式或纯展示行为发生变化，需要在同一次变更中更新本文档。

## 入口与总体结构

- 前端技术栈：React 19 + Vite + TypeScript + Tailwind CSS + lucide-react icons。
- 主入口：`frontend/src/main.tsx`。
- 主要实现：`frontend/src/App.tsx`。
- 全局样式：`frontend/src/styles.css`。
- 离线/刷新缓存：`frontend/public/sw.js` 负责静态资源缓存与页面刷新时的兜底。
- API 封装：`frontend/src/api/*.ts`，共享请求、错误解析、查询参数和 GET 缓存逻辑集中在 `frontend/src/api/client.ts`。
- 展示配置：分页数量、导航项、排序字段和状态选项集中在 `frontend/src/uiConfig.ts`。
- Markdown 渲染：`frontend/src/components/MarkdownPreview.tsx` 和 `frontend/src/utils/markdown.ts`。
- Markdown 围栏代码块会保留原始换行与每行前导空格；清理泄漏的内部代码占位符不能压缩其它 Markdown 空白，确保 Python、YAML 等嵌套代码在预览中保持缩进。
- 共用 Markdown 预览会将 ` ```mermaid ` 围栏渲染为 Mermaid SVG 图表；图表下方保留可展开的原始源码，右上角“复制”仍复制源码。单图源码超过 20,000 字符或解析失败时不执行图表渲染，并显示原因与源码回退。图表渲染使用 Mermaid 严格安全模式，深浅主题均有适配。
- 带语言标识的代码围栏会按 Bash/Shell、Python、SQL/PLSQL、JavaScript/TypeScript、JSON、HTML/XML、CSS、YAML、Markdown 展示关键字、字符串、注释和数字高亮；未知语言继续按普通代码显示，绝不对未标识代码自动猜测语言。
- 所有共用 Markdown 预览中的围栏代码块右上角均提供独立“复制”按钮；它只复制该代码块的纯文本，不包含围栏标记或语言标识，并会显示短暂的成功或失败反馈，方便将命令、SQL 或代码送至受控环境校验。
- 单下划线斜体仅在独立 Markdown 标记中生效；变量名、路径和文件名中的词内下划线（如 `v_needs_update`、`my_file_name.md`）按普通文本显示，避免预览、富文本复制和增强 HTML 导出出现误斜体。
- 博客工厂的增强美化 HTML 离线导出脚本为 `scripts/export-enhanced-html.mjs`；它与应用内增强美化渲染同步支持 H1-H4、代码块缩进、表格、图片内联和 `$$...$$` LaTex 公式块，修改该渲染能力时须在同一次变更中同步脚本。
- 博客工厂“增强美化”在浏览器中生成的下载 HTML 与富文本复制，会将 Mermaid 图表转为内嵌 3 倍像素密度 PNG，并默认按比例尽量填充 960×720 的逻辑显示区域、在窄屏自动缩小，方便离线打开和粘贴到第三方编辑器且保持文字清晰；代码块在剪贴板 HTML 中不携带高亮 span，以保留空格和缩进。命令行 `scripts/export-enhanced-html.mjs` 仍以内嵌 Mermaid runtime 的方式生成独立 HTML。后端博客发布仍保留 Mermaid 源码代码块，不在该链路执行浏览器图表渲染。
- Markdown 图片：可信知识和 Todo 正文仍保存为文本 Markdown，图片由后端媒体 API 上传到本地媒体仓库，正文中插入 `/api/media/{public_id}/content` 形式的图片链接。
- Markdown 工具栏在应用标题、列表、代码、表格、注释或图片插入后会恢复选区，并保留当前编辑区的横向和纵向滚动位置；长文编辑不会因格式化跳回首行。
- 可信知识编辑和待办任务内容的 Markdown 编辑 / 预览模式可用快捷键切换：macOS 为 `⌘ + \\`，Windows/Linux 为 `Ctrl + \\`；仅在对应内容编辑器打开时生效，按钮悬停提示会显示该快捷键。

当前前端大部分逻辑集中在一个较大的 `App.tsx` 文件中。它同时承载导航、状态恢复、数据加载、视图切换和大部分页面组件。项目没有使用 React Router；当前工作区由 `activeView` 控制，并持久化到 localStorage 的 `trustedKnowledge.uiState.v2`。
- 该 UI 状态同时保存信息录入、知识加工、博客工厂、待办事项和英语素材各自的用户筛选值；英语素材还会保存详情打开状态与选中 ID；个人机密保存搜索词、页码、选中 ID 与移动端详情打开状态，不保存明文机密字段。
- PWA 切至后台时会保存页面与个人机密详情的滚动位置；若 iOS 回收 WebView，重新启动时优先还原已缓存的总览和列表数据。英语素材详情会优先从该条目的本地缓存立即恢复，后台再读取最新数据；其 URL 使用 `english_material_id` 查询参数定位，刷新或重新打开仍可恢复到相同详情。用户点击刷新或完成本机写入操作后仍会读取最新数据。

整体视觉默认是深色工作台风格，并支持用户切换到浅色主题：

- 背景：`ink-950` / `ink-900` 深色面板，搭配低饱和 mint 强调色。
- 主题：顶部栏提供太阳/月亮按钮，可在深色与浅色主题之间切换；当前选择持久化到 localStorage。
- 浅色主题会额外提高次级按钮、禁用按钮和 `amber` 操作按钮的前景/边框对比度，避免深色主题中常见的幽灵按钮配方直接迁移后变得过淡。
- 同一套浅色主题补偿也覆盖常见的标签 chip、空状态提示、虚线辅助面板和 Markdown 预览容器，减少局部区域“背景已变浅、文字却还偏灰”的问题。
- 浅色主题下的 sky 状态标签与通用确认弹窗也会单独提升对比度，避免 Todo `处理中` 和 `转为知识` 一类确认动作继续显得模糊。
- 浅色主题下所有复用 `z-50` 全屏遮罩的按钮触发弹窗，会统一把 `bg-ink-900` / `bg-ink-900/96` 面板和 `bg-black/60` / `bg-black/62` 遮罩替换为浅色表面，避免博客工厂 `配置API`、`发布到博客` 以及其它详情/确认弹窗残留深色外观。
- 应用刷新时会在 React 挂载前先读取并应用已保存的主题模式，保证浅色主题下的加载骨架与初始页面背景不会短暂回退成深色。
- 除应用内骨架屏外，`frontend/index.html` 中的静态 `Trusted Knowledge / 加载中...` 启动占位页也会读取同一份主题状态，确保手工刷新时启动页与应用主题一致；启动期间会锁定页面纵向溢出，仅显示居中动画，React 挂载完成后自动恢复应用内滚动。
- `frontend/public/sw.js` 对 HTML 与应用壳采用带 450ms 上限的网络优先策略：快速网络响应时使用最新页面；超过上限时先使用已缓存页面并继续后台更新，离线时同样回退到缓存页面。对 `/assets/` 下带 hash 的静态资源采用 `stale-while-revalidate`，优先秒开已缓存资源，并在后台补更最新文件。
- 面板：主要使用 8px `rounded-lg`、半透明白色边框和克制阴影。
- 布局：桌面端是固定左侧栏 + 顶部栏；移动端隐藏侧栏，在顶部栏中展示可折叠的网格导航。
- 信息录入、知识加工、博客工厂、待办事项、个人机密、英语素材和 Skill 管理的桌面 `xl` 双/多栏工作区均支持收起左侧主面板：展开时点击左侧工作区外框右缘的 28px 全高轨道即可收起，收起后点击同宽轨道恢复；轨道始终附属于其对应的面板外框，窄于 `xl` 时始终保留完整面板，保证移动端列表、录入和操作可达。
- 顶部栏：中文页面标题直接复用左侧导航的模块标签，避免维护两套文案；桌面端使用更紧凑的上下间距和标题字号，移动端保持原有尺寸。右侧操作区会持续显示当前登录用户名，使用低对比度身份条样式，放在退出按钮左侧；点击该身份条可随时返回总览，移动端会同时收起已展开的功能导航。
- 表单控件：统一使用 `styles.css` 中的 `.control`，移动端输入字号固定为 16px，避免 iOS 自动放大。
- 历史查询、英语素材与博客工厂的可展开筛选区均提供提交式“近似检索”：输入查询后点击统一的“搜索”按钮或按回车才会执行，避免输入过程中重复请求；它与顶部普通关键字搜索独立，按向量相似度排序并在卡片中展示分数。英语素材在桌面端将近似检索/用户/分类与状态/排序/清空操作分成两行，近似检索占用主宽度而用户、分类保持紧凑，避免排序控件被压缩；清空筛选会同步清空近似检索，移动端仍在可展开筛选内保持可达。
- 历史查询、英语素材和博客工厂的近似检索列表均提供“向量状态”（全部、待更新、已就绪）筛选，并在所有结果卡片显示同款状态标签；管理员可在三处筛选区标题栏以同款“刷新向量”按钮执行对应刷新过程，操作期间显示刷新中并在完成后重新加载当前列表。非管理员不显示全量刷新按钮。
- 下拉框会在 `.control` 的基础上单独收紧纵向 padding，并保持固定行高，避免 `h-10` 一类固定高度选择器出现文字下沿被裁切。
- 图标：导航、按钮、状态和空状态统一使用 lucide-react。

## 导航模型

导航项由 `frontend/src/uiConfig.ts` 中的 `FUNCTION_NAV_ITEMS` 定义。

| View key | 页面名称 | 主要用途 |
| --- | --- | --- |
| `overview` | 总览 | 聚合 LLM 用量、Todo、英语素材和可信知识的 Dashboard。 |
| `workbench` | 信息录入 | 新增/编辑可信知识，也可以用同一个录入表单新增 Todo。 |
| `factory` | 知识加工 | 选择未发布知识和 Skill，生成加工结果；运行时显示已等待时间和最近活动，60 秒无活动会提示可取消重试。 |
| `blogFactory` | 博客工厂 | 查看已保存的博客工厂任务、状态、任务快照和博客发布动作。 |
| `todos` | 待办事项 | 列表、筛选、编辑、复制、转换 Todo 记录。 |
| `personalSecrets` | 个人机密 | 存储和检索个人登录信息，支持字段复制和整体复制。 |
| `currentRecords` | 当前记录 | 管理当前学习记录，编辑 week/day/content 进度。 |
| `history` | 历史查询 | 筛选、排序、查看历史记录和详情元数据。 |
| `englishMaterials` | 英语素材 | 新增、列表、筛选、编辑和复制英语素材。 |
| `aiGraph` | AI 图谱 | 以图谱方式展示当前项目功能模块实体、数据流和权限关系。 |
| `users` | 用户管理 | 仅 super admin 可见；管理 `TK_USERS` 用户、admin 角色授权、AI 编程/AI 用量模块授权，以及 `TK_RELATIONS` 家长关系。 |
| `skills` | Skill 管理 | 创建、上传、编辑、删除 Skill 包和文件。 |
| `historyAsk` | AI 问数 | 基于历史记录做自然语言问答，可选择执行模型、Skill 和 OpenAI 兼容模型配置。 |
| `aiCoding` | AI 编程 | 默认仅 super admin 可见；可由 super admin 授权给 admin 角色用户访问 Codex 编程任务。 |
| `usage` | AI 用量 | 默认仅 super admin 可见；可由 super admin 授权给 admin 角色用户查看 LLM 用量采样和重置状态。 |

### Skill 管理 / `skills`

- 左侧面板仅保留 Agent / Skill 切换、范围筛选和列表；选择 Skill 后，右侧详情标题栏提供“新建 Skill”和“导入 Zip”，避免创建与上传操作挤占列表空间。
- 新建和导入均使用独立响应式弹窗：窄屏以底部 Sheet 展示，长 `SKILL.md` 编辑区在弹窗内滚动，提交与取消操作保持可达。
- “新建自定义 Skill”在已填写名称与描述后提供“AI 创建”按钮；弹窗沿用 AI 补全交互，可选择执行模型和最多一项 `skill-generation` Agent 允许调用的创建规范 Skill。
- 生成结果先在弹窗中预览，点击“确认回填”才会填入 `SKILL.md` 编辑框；它不会自动创建或保存，用户仍可编辑并通过“新建 Skill”完成最终确认。
- 管理员可在“Agent 与 Skill”为 `skill-generation` 配置或更新创建规范 Skill；下一次生成会使用其当前保存内容。

### 博客工厂 AI 增强

- 在“编辑任务内容”旁提供独立的 `AI 增强`，与仅产生局部替换建议的 `AI 审阅` 分开；它可选择执行模型及 `blog-enhancement` Agent 所允许的增强 Skill。
- AI 增强预览完整的增强版 Markdown，适合在 `mermaid生成@Aflred` 等 Skill 指引下于合适位置插入 Mermaid 图表。确认回填后只进入编辑状态，用户必须点击“保存任务内容”才会更新数据。
- 管理员可在“Agent 与 Skill”更新 `blog-enhancement` 关联的 Skill；后续增强请求会立即采用其保存内容。

桌面侧栏：

- Visible at `lg` and above.
- Can collapse to icon-only mode.
- `AI 用量` is placed as a bottom utility entry.
- 当前有两个仅展示的工具按钮：`Review` 和 `Sources`，没有切换视图的行为。

移动端顶部导航：

- “显示导航 / 隐藏导航”开关固定在顶部栏右上角，不占用独立行；标题区预留右侧空间，避免长标题被控件遮挡。
- 展开后以 2 列或 3 列按钮网格展示所有 `FUNCTION_NAV_ITEMS`。
- 点击某个移动端导航项后，会切换视图并自动收起导航。
- 在没有桌面侧栏时，仍然保持核心导航可访问。

顶部搜索：

- 在 `overview`、`usage`、`historyAsk`、`aiCoding` 中隐藏。
- 在数据列表类页面中显示，并写入对应页面的 query 状态。
- `workbench` 的用户与状态筛选位于“已录入知识”面板内，默认折叠；展开后可按需调整，并在收起状态显示已生效筛选数量。

## 主要页面

### 总览 / `OverviewDashboard`

布局：

- 顶部显示刷新按钮和最后更新时间。
- 两个指标卡片：
  - 处理中 Todo
  - 未发布知识
  - 手机端 PWA 与桌面端均按每行 2 张卡片显示。
- 有 AI 用量查看权限时，手机端标题行右侧显示紧凑的 LLM 剩余额度电池，桌面端则与右侧刷新操作对齐；电池填充和内部显示的整数百分比均表示剩余容量，点击可进入 AI 用量详情，剩余低于 20% 时切换为红色预警。
- 主体网格：
  - 桌面端以等宽双列与上方指标卡对齐：左侧为 `处理中 Todo` 卡片列表，右侧为 `可信知识` 未发布知识卡片。
  - 窄屏保持单列堆叠，避免卡片内容和操作控件被压缩。
- 底部通栏：
  - `最近 English` 素材卡片列表和显示数量控制。

数据来源：

- `fetchLlmUsage(USAGE_SAMPLE_LIMIT, false)`
- `fetchTodos({ username: authUser.username, status: "处理中", limit: OVERVIEW_TODO_LIMIT, offset: 0, includeTotal: true })`
- `fetchKnowledge({ username: authUser.username, status: "未发布", limit: OVERVIEW_KNOWLEDGE_LIMIT, offset: 0, includeTotal: true })`
- `fetchEnglishMaterials({ username: authUser.username, sortBy: "id", sortDir: "desc", limit: overviewEnglishLimit, offset: 0, includeTotal: false })`

当前行为：

- 总览内各模块目前不分页。
- 总览 Todo 只显示 `处理中` 状态，指标卡显示该状态的精确总数，列表仍只展示最近 `OVERVIEW_TODO_LIMIT` 条。
- English 模块默认显示最新 3 条；可在分区内切换为最近 1、3、5 或 8 条，切换后按所选数量重新读取并渲染。
- 可信知识模块只显示 `未发布` 状态，指标卡显示未发布知识精确总数，列表使用 `OVERVIEW_KNOWLEDGE_LIMIT` 控制卡片数量。
- English 和 LLM 用量仍使用轻量读取；English 仅加载当前选定数量的最近素材。
- 总览中的 Todo、可信知识和英语素材会固定收敛到当前登录用户名，只展示“我自己的数据”；不会再默认汇总其他可见用户的数据。
- 分区失败会独立展示错误，一个数据源失败不会阻断整个总览。
- 点击卡片会跳转到对应完整工作区，并在支持的页面中选中对应记录。

### AI 图谱 / `aiGraph`

布局:

- 独立懒加载视图：`frontend/src/views/AiGraphWorkspace.tsx`。
- 桌面端主体为 SVG 连线图 + 绝对定位模块节点，右侧为选中模块详情、关联关系和推荐阅读路径。
- 移动端保留横向滚动图谱区域，避免节点和连线被压缩到不可读。

功能:

- 把当前项目主要功能模块作为实体节点展示，包括总览、信息录入、知识加工、博客工厂、待办事项、当前记录、历史查询、AI 问数、Skill 管理、英语素材、个人机密、AI 编程、AI 用量、用户管理和 AI图谱自身。
- 节点按中枢、内容生产、AI 能力、记录沉淀、安全治理分组，并使用当前主题下的 mint / sky / fuchsia / amber / emerald 色系区分。
- 点击节点会高亮直接关系，右侧展示模块说明和关联边；点击 `打开模块` 可切换到对应工作区。
- 当前为纯前端静态拓扑图，不读取后端接口，不改变模块鉴权、API 字段、数据库结构或业务数据。

### 信息录入 / `workbench`

桌面布局:

- 主网格包含知识表单、知识列表和可信度面板。
- 在 `xl` 断点变为 3 列：表单、列表、可信度面板。
- 低于 `xl` 时，面板会折叠为更少列。
- 桌面 `xl` 下，左侧信息录入表单可通过右缘 28px 轨道收起，腾出空间给知识列表和可信度面板；收起后两个面板共同分配并填满剩余工作区宽度，轨道可随时恢复表单。
- 桌面 `xl` 下，右侧的“已录入知识”和“可信度检查”也可作为一个整体通过最右侧 28px 轨道向右收起；收起后信息录入表单扩展为主工作区，轨道可随时恢复右侧面板。窄于 `xl` 时不显示该折叠轨道，保持现有可达布局。
- 手机端 PWA 的“录入可信知识”区域默认展开；标题右上侧提供收起/展开控件，收起时隐藏内联 Trust 百分比，已录入知识列表保持可访问。

功能:

- 新增可信知识。
- 新增时可勾选 `这是待办事项`，写入 Todo 而不是可信知识库。
- 勾选 `这是待办事项` 后，表单会显示待办状态选择，默认值为 `处理中`，也可切换到 `待处理` 或 `已完成`。
- 可信知识的标签字段在保存前校验仅含英文字母、数字、下划线、英文逗号和空格；非法标签或旧数据、旧页面触发的 `CK_TOPIC_TAG` 数据库错误会显示英文逗号分隔规则的可读提示。
- 可信答案 / 待办事项内容编辑器提供统一的紧凑 Markdown 工具栏：`Markdown` 标识单独显示在首行，全部格式化与图片上传操作在下一行自动换行。它可将当前选区（未选中时使用光标所在行或插入模板）快速设为 H1/H2/H3、加粗、行内代码、代码块、无序/有序/任务列表、引用、表格或 HTML 注释；对已应用同一格式的选区再次操作会取消该格式，行选区末尾的换行不会影响下一行（包括加粗标记）。多行有序列表会连续编号；表格保持自动选中时，再次点击会还原为表格正文首列的纯文本行。工具栏采用深浅主题均清晰可读的层次化按钮，移动端核心操作仍可完整触达。
- 可信答案 / 待办事项内容编辑器支持选择本机图片和粘贴剪贴板图片；上传成功后自动在光标位置插入 Markdown 图片语法。
- 编辑选中的可信知识。
- 保存可信知识在 15 秒内未收到响应时会提示“保存结果可能未知，请刷新确认后再重试”；保存不自动重试，避免未知提交结果覆盖内容。若同一记录正被另一保存请求占用超过 5 秒，会显示明确的稍后重试提示。
- 编辑可信知识时，`可信答案` 支持在“编辑”和“Markdown 预览”之间切换；预览会渲染标题、列表、链接、代码块、表格及 Markdown 图片，便于保存前确认显示效果。
- 二次确认后删除选中的可信知识。
- 将选中的可信知识转为 Todo。
- 支持上一条/下一条，并可跨当前分页边界切换。
- Trust 分数和敏感信号由前端基于草稿内容计算。
- 可信知识和 Todo 数据由后端按 `USER_ID` 过滤；普通用户创建的数据归属当前登录用户。
- 列表新增按用户筛选；普通用户默认先看自己的数据，再按需切到孩子或全部可见用户。

列表行为:

- 服务端分页。
- 默认每页数量：`PAGE_SIZE = 5`。
- 用户与状态筛选：位于“已录入知识”区域的默认折叠“查询条件”面板中；状态选项为 `全部状态`, `未发布`, `已发布`, `跳过`，收起时显示已生效筛选数量。

移动端行为:

- 选择知识条目会打开移动端编辑弹层，列表和编辑动作都保持可达。

### 知识加工 / `factory`

- 桌面 `xl` 下，待加工知识列表可通过右缘 28px 轨道收起，知识原文、加工结果和 Skill 区保留完整可用宽度；窄屏始终显示列表。

桌面布局:

- 左侧：未发布知识队列。
- 中间：选中知识的原文上下文。
- 中间原文区：执行模型、Skill 下拉选择和生成结果按钮；操作区会按可用宽度自动换行，避免桌面窄列或手机端按钮越界；右侧：仅展示加工结果。

功能:

- 只列出 `未发布` 知识。
- 支持搜索。
- 支持按用户筛选未发布知识；普通用户默认先看自己的数据，再按需切到孩子或全部可见用户。
- 支持多选和合并所选知识。
- `知识原文` 标题区提供“上一条 / 下一条”按钮，可按当前待加工队列和筛选结果连续切换，跨页时自动载入相邻页的首条或末条记录。
- 合并知识弹窗的素材编辑区同样支持选择或粘贴图片，并将图片链接保留在合并后的 Markdown 正文中。
- 生成前必须通过下拉列表显式选择一个 Skill；执行模型同样通过下拉列表选择，并位于生成结果按钮之前。
- 生成结果可以选择执行模型：默认沿用 Codex CLI 默认模型，也可以选择 Codex 预设模型，或选择唯一的“其他模型”。后者会使用 AI 问数中已启用的 OpenAI 兼容供应商、Base URL、模型名和后端 API Key，而非传递模型名给 Codex CLI；选择会随知识加工 UI 状态保存在浏览器中。
- 生成时以 read-only 模式运行 Codex，提交给 Codex 的 prompt 最多 50,000 字符。
- 知识加工会请求 Codex 返回最终消息而不是中间执行日志，结果区默认避免展示“先读取 skill / 分析任务”这类 agent 过程文本。
- final 模式下会把所选 Skill 文本直接内联进 prompt，而不是让 Codex 再自行读取 `SKILL.md`，以降低过程说明泄漏并提高 Skill 规则命中率。
- 调用级 prompt 会把“Markdown 图片链接必须逐字保留”作为硬约束，避免 Skill 文章重写时误删原素材中的 `![](media/...)` 图片行。
- 生成结果支持 Markdown 美化展示和裸文本展示。
- 生成结果会清理泄漏的 Markdown 内部代码占位符，避免 `@@CODE0@@` 或私有 Unicode 包裹的 `CODE0` 这类标记进入展示、复制或保存内容。
- 展示前还会额外清理常见的过程型前置说明，以及将被 Skill 禁止的“按现有素材来看”“素材中的做法”等话术替换为更贴近 `笔者环境` 的表述。
- Markdown 美化预览支持常见 Markdown 图片语法，并允许相对路径图片地址（如 `media/...`、`./...`、`../...`）进入渲染链路。
- 生成结果成功完成后会自动保存为博客工厂任务；复制动作只负责复制富文本 Markdown 或裸文本，若自动保存失败也会作为手动重试入口。
- 自动保存到博客工厂后，会立即把对应源知识的内容状态同步为 `已发布`，这样该记录会从“知识加工”的未发布队列中移出。
- 未发布知识队列按当前登录用户可见范围过滤；保存到博客工厂时继承源知识的 `USER_ID`。

列表行为:

- 服务端分页。
- 默认每页数量：`FACTORY_PAGE_SIZE = 6`。

### 博客工厂 / `blogFactory`

桌面布局:

- 左侧：博客工厂任务，标题区下方提供默认折叠的查询条件（用户、状态、标签、知识 ID、排序和清空）；用户可按需展开，已有筛选会在折叠状态以数量提示保留可见性。桌面 `xl` 双栏下任务列表默认展开；左侧面板右边缘内嵌整条可点击的 28px 收起轨道，收起后左侧保持同宽的 28px 可点击展开轨道，轨道仅保留箭头提示，右侧任务内容区随即占用剩余宽度。窄于 `xl` 时始终显示完整任务列表。
- 右侧：更宽的任务详情主工作区（桌面端最小 600px），任务内容预览、复制、内容辅助与博客发布工具区置于详情最上方，工厂状态动作和任务快照编辑区在其后。

功能:

- 按用户、工厂状态、主题标签、知识 ID 筛选。
- `任务详情` 标题区提供“上一条 / 下一条”按钮，可按当前筛选和排序连续查看任务，跨页时自动载入相邻页记录。
- `清空筛选条件` 会把用户筛选恢复到 `全部可见用户` / `全部用户`；如果当前账号只可见 1 个用户，则保持该唯一用户。
- 移动端筛选区会将排序字段独占一行，方向与 `清空筛选条件` 并列等宽展示，避免 PWA 窄视口溢出且保持操作可达。
- 按复制时间、ID、知识 ID 或工厂状态排序。
- 任务列表标题优先显示已保存文章的标题，其次显示当前任务内容中的 Markdown 一级标题；只有两者均不存在时才回退到“原始问题”，以兼顾二次编辑后的可见标题与原始加工问题的追溯。
- 任务内容面板保留美化模式、复制、内容辅助、封面与发布操作，并提供 `编辑任务内容` 入口；点击后原地切换为最小高度 420px 的共享 Markdown 编辑器，支持通过工具栏插入图片或直接粘贴剪贴板图片，上传后插入 Markdown 图片引用。编辑状态提供 `取消编辑` 和 `保存任务内容`，保存成功后返回预览。来源、主题标签、问题快照与答案快照作为原始任务元数据继续保留，但不在此编辑区展示；来源和主题标签仍用于发布、筛选和发回知识加工。`内容辅助` 的摘要独立保存到工厂任务，支持提取、手动编辑和保存；封面上传、替换和移除同样独立保存，不会自动写入任务内容，只有用户主动在编辑器中插入图片时才会进入正文。两项保存均为独立部分更新，不受任务正文或快照是否完整影响；按钮会就地显示“保存中”、“已保存”或“保存失败”。摘要数据库字段按 100 个字符存储，支持最多 100 个中文或英文字符；每个按钮只显示自身请求的动态状态，且并发返回时只合并自身字段，避免互相覆盖界面数据。
- `AI Review` 在桌面端以顶部对齐的审阅工作台打开，移动端保持底部抽屉可达；审阅前可选择执行模型和当前用户可调用的 Skill。它会基于当前任务内容及问题/答案快照审阅结构、逻辑、表达、一致性与 Markdown；结果不会自动写入。使用 DeepSeek 时会请求 JSON 模式，并兼容其等价英文标签或一层结果包装。每条可应用建议均包含定位原文和精确替换文本，用户可勾选部分建议；应用后仅更新本地草稿并切换到编辑模式，仍须通过 `保存任务内容` 写入。原文无法唯一定位时不会替换，以避免误改。
- 任务内容的编辑态中，脱敏工具位于编辑工具栏的紧凑`脱敏`按钮内；点击后才显示规则选择、规则管理、规则说明与应用操作。取消编辑、保存任务或切换任务后会重新收起。
- 更新工厂状态：`待处理`, `已处理`, `已发布`, `跳过`。
- 待处理任务详情可执行 `发回知识加工`：前端提交当前任务内容和快照，后端在同一用户归属下创建新的 `未发布` 知识加工项，并把当前博客工厂任务标记为 `跳过`；操作成功后页面会切换到“知识加工”并选中新创建的知识。
- 从知识加工发送过来的任务会自动把内容状态记为 `已发布`；博客工厂详情页不再提供单独的内容状态切换，只保留工厂状态维护。
- 任务详情中 `任务内容` 区域固定显示在最上方，便于优先查看正文、复制、处理封面/提示词并进入发布流程；`美化` / `增强美化` / `裸文本` 控件下方固定提供 `提取摘要`、`生图提示词` 和 `发布到博客` 快捷操作，前两项会在当前任务详情加载完成后平滑定位到对应辅助区，发布操作直接打开原有发布弹窗；快速切换任务时，旧任务的详情响应会被忽略。
- 任务内容区新增独立的 `博客发布` 工具区：放置 `配置API` 与 `发布到博客` 入口，不再和 Markdown 正文编辑按钮混排。
- 发布成功或失败反馈显示在按钮组下方的独立提示条中，避免桌面端提示文案挤压发布按钮。
- `配置API` 会打开 Metaweblog API 配置弹窗，支持维护多套博客发布配置，字段包括博客类型（当前固定为 `Metaweblog API`）、博客网址、账号、密码、API 地址、博客名称，以及“设为默认配置”开关。
- 配置弹窗支持 `新增`、切换、更新、删除和 `验证`；验证会调用后端 Metaweblog 校验接口，成功后回填博客名称并提示当前连接到的博客站点。
- 博客发布配置读取会优先按当前登录用户的稳定 `user_id` 匹配，并兼容回退到旧行的 `owner_username`，保证同一账号跨设备看到同一套配置。
- 任务内容区中的 `发布到博客` 会打开发布弹窗，允许在已保存配置之间切换，并选择将当前正文保存为草稿或直接发布。
- 当所选发布配置是博客园时，发布弹窗会额外显示 `投稿选项`，默认值为 `投稿至博客园首页`，也可切换为仅发布到个人博客。
- 当所选发布配置是博客园时，发布弹窗还会读取该博客账号下的个人分类列表，但前端仅保留 `随笔分类` 条目供勾选；是否投稿到博客园首页由上方 `投稿选项` 控制，后端会在发布时自动同步博客园特殊的 `发布至博客园首页` 分类。
- 发布弹窗中的 `Tag 标签` 与博客园个人分类分离：`随笔分类` 只写入博客分类，`Tag 标签` 独立来源于任务记录中的 `主题标签`，支持在发布前单独调整，不再把 `[随笔分类]...` 或 `发布至博客园首页` 混入标签。
- 博客园个人分类列表会在前端按配置 ID 做短期缓存，并在博客工厂页预热默认配置，减少每次打开发布弹窗时等待分类接口的时间。
- Metaweblog 发布会把远端 `post_id`、上次使用的发布配置、投稿选项、个人分类和 Tag 标签回写到博客工厂记录；之后再次 `保存草稿` 会更新同一篇远端草稿，已保存草稿点击 `确认发布` 会直接在原文章上切换为正式发布，弹窗也会自动回填这些上次使用的参数。
- `博客发布` 按钮下方的辅助说明在浅色主题下使用已适配的 slate 文本色阶，避免文章标题/发布来源提示在浅色背景中发灰不清晰。
- 发布正文来源规则：优先使用已保存的 Markdown 文章；如果没有已保存文章，则回退到当前任务内容。
- 发布时会优先从 Markdown 一级标题提取文章标题，并默认从正文中去掉开头的同名一级标题，避免目标博客页面出现重复标题。
- 当目标博客配置指向博客园时，发布请求会默认按 Markdown 文章格式发送正文，而不是先转成 HTML。
- 发布正文包含本系统 `/api/media/.../content` Markdown 图片时，后端会在调用 MetaWeblog 发文前先上传图片到目标博客媒体库，并把正文中的本地图片链接替换为目标博客返回的远端图片 URL，避免外部博客页面解析成 `cnblogs.com/api/media/...` 这类不可访问地址。
- 成功发布后，详情区会显示返回的博客名称和文章 ID，同时把关联博客工厂记录与原可信知识的发布状态同步更新为 `已发布`。
- 删除选中的博客工厂任务记录，不删除原可信知识内容。
- 查看任务内容时默认选择 `增强美化`；`美化` 和 `增强美化` 模式会直接显示渲染后的 Markdown 预览，切回 `裸文本` 时保留原始文本视图。
- 博客工厂任务内容的 Markdown 渲染与两种富文本复制链路支持 `$$...$$` LaTeX 公式块，会把常见公式命令（如 `\\text{}`、`\\frac{}`、`\\sqrt{}`、上下标和常用符号）渲染为独立公式卡片。
- 可选择复制 Markdown 美化富文本、增强美化富文本或裸文本；问题快照、答案快照、来源和标签继续按原样查看。
- 任务内容区提供 `内容辅助`：可基于当前编辑框内容提取不超过 100 字的摘要，并生成可复制的文章识别型封面生图提示词；低频的封面图片上传/粘贴区位于两项结果之后，上传后会以 Markdown 图片格式写入任务内容草稿。生图提示词页可粘贴任意文章标题、摘要或正文片段，留空时回退使用当前任务内容；默认只输出“标题”“文章核心讲什么”“想要的感觉”三项，不再拼接构图、材质、镜头、质量等长视觉参数。`文章分类预设` 覆盖公开课、AI、APEX、Oracle、效率工具箱、英语、Data、Linux 八类，选择后分别带入清透极简商务、暗黑赛博科技、轻白产品哑光、暖调工业哑光科技、彩色模块化工具台、纸艺拼贴学习卡、数据新闻玻璃图谱、复古终端像素工程；仍可通过 `画面风格` 下拉手动覆盖。默认模板仅使用 `{{title}}`、`{{summary}}`、`{{style}}` 三个变量，并可恢复默认。
- `内容辅助` 的 `提取摘要` / `生图提示词` 切换按钮在桌面端按内容宽度保留完整文案；移动端保持等宽全行布局，避免中文标签被压缩或裁切。

- 新建普通用户或家长用户，并可额外授予独立的 admin 角色。

- 配置 `AI 编程`、`AI 用量` 是仅 super admin 可见，还是也允许 admin 角色用户可见。

- 用户列表不分页，随接口返回整体展示。

### AI 问数 / `historyAsk`

功能:

- 模块英文标识使用 `Ask Data`，体现其不再局限于历史记录查询。
- 基于受控业务域数据进行自然语言问答。
- 支持选择受控业务域：`历史工作记录`（`T_HISTORY`）、`待办事项`（`AI_TODO_ITEMS`）、`可信知识`（`AI_QA_LIB`）和 `英语素材`（`T_ENGLISH`）。各业务域由后端固定适配器查询，不允许用户提交表名或 SQL；待办域使用状态、标签和创建日期，可信知识使用发布状态、主题标签和创建日期，英语素材使用标记状态和分类作为统计维度。
- 业务域选择框下会展示后端注册的数据来源表，例如历史域的 `T_HISTORY`、`TK_USERS`、待办域的 `AI_TODO_ITEMS`、`TK_USERS`、可信知识域的 `AI_QA_LIB`、`TK_USERS` 与英语素材域的 `T_ENGLISH`、`TK_USERS`，并明确标注为受控只读数据源。
- 执行模型下拉与知识加工复用同一套 Codex CLI 默认/预设模型选项，并额外提供“已配置模型”；后者使用右侧已启用的 OpenAI-compatible 配置，前者以 read-only 模式调用 Codex CLI。两种执行器都只能获得后端已检索的统计和证据摘录，不会直接执行任意 SQL。
- AI 问数首次进入时的执行模型默认选中 `CLI 默认`；用户仍可手动选择 Codex 预设或“已配置模型”。
- 桌面端的业务域与执行模型选择器位于“自然语言问数”标题右侧，便于在提问前快速确认上下文；业务域数据来源和模型执行方式显示在标题下方的紧凑说明行。移动端改为在标题下自动换行，保留完整可操作宽度。
- Skill 选择、模型配置与业务概念维护默认折叠，避免首次进入时稀释问题输入区；执行后，右侧栏仅保留简洁查询摘要，完整统计、图表与记录在主结果区展示。结果工具栏将 SQL 与提示词查看归入“审计”。
- 展开调用 Skill 后，卡片在移动端保持单列、满宽且可收缩；较长的名称、描述和所有者文本会截断或换行，不能突破右侧边界。桌面端从 `sm` 宽度起恢复双列展示。
- 收起调用 Skill 区域且存在选择时，数量旁会显示已选 Skill 的紧凑名称标签；长名称保持截断，避免影响移动端操作按钮。
- 问题输入框下方的“快捷问题”支持按当前登录用户和当前业务域维护。用户可新增、编辑、删除最多 12 个问题；存在自定义问题时仅展示该业务域的自定义列表，否则展示系统示例。
- 提问时可选择已启用的 Skills。
- 未选择任何 Skill 时，结果区默认展示基础查询结果：匹配记录、活跃日期、日期范围、类型/周期分布条形图和实际命中记录（当前在单次受控查询中最多返回 80 条，并可在前端分页查看）；选择 Skill 后保留其定制化 Markdown 回答展示。
- 结果工具栏可按需展开“显示 SQL”和“显示提示词”：SQL 区只展示后端固定只读模板及脱敏绑定参数；提示词区展示系统提示词与完整查询上下文，可核对命中的轻量本体概念、Skill 指令和事实摘录。二者均不可在页面中编辑或执行。
- 回答支持 Markdown 美化展示和裸文本模式。
- 结果区顶部会展示本次参与问数的 Skill 与命中业务概念标签；浅色主题下 sky 与 fuchsia 标签，以及 SQL 审计标题，使用更深的前景色，避免名称在浅背景上发白不可见。
- 可复制富文本 Markdown 或裸文本。
- 结果区的业务记录跳转会跟随当前业务域：历史记录进入历史查询，待办进入待办事项，可信知识进入信息录入的知识列表，英语素材进入英语素材列表；仅传递目标页面可识别的关键词、用户和状态类条件。
- 可查看和编辑 OpenAI-compatible LLM 配置，API key 由后端环境配置处理。
- 可在右侧维护当前业务域的轻量业务概念：默认是仅自己可见的个人词典；也可创建指定用户名可用的团队词典；管理员可维护全员可用、普通用户只读的系统词典。检索会合并三层词典，同名概念以个人、团队、系统的顺序覆盖。提问命中概念或别名时，问数会扩展为这些名称的并集检索，并将口径作为受事实边界约束的上下文交给 AI；结果会展示命中的概念标签。
- 历史记录检索范围跟随当前登录用户：普通用户和家长管理员只能基于可见用户范围提问，`admin` 可基于全部历史记录提问。

### AI 编程 / `aiCoding`

布局：

- `项目变更日志` 位于左侧主工作区的任务结果下方，使用主栏宽度展示 Markdown；右侧栏仅保留代码同步与服务操作，避免长日志挤压操作区。
- 顶部仅保留 `执行模型` 下拉框；AI 编程页不再读取或展示 CLI 当前默认模型，避免默认模型配置读取影响任务输入。
- 没有任务输出或用户已清空当前展示时，不渲染任务结果空状态卡；项目变更日志会紧接任务提交区，避免无效占位。

移动端结果摘要行为：

- AI 编程任务完成后的摘要卡片中，`重启判断` 与 `变更文件` 两个区块在手机竖屏下会保持单列并限制在容器宽度内。
- `变更文件` 中的长路径会在卡片内部截断显示，不应再把整张结果卡片撑出右侧屏幕边缘；横屏与桌面端继续沿用现有更宽布局。

可见性:

- 默认仅 `admin` 超级管理员可见。
- 如果用户管理中的模块授权设置为 `admin 用户 + admin 角色`，则拥有 admin 角色的普通用户也可见。

功能:

- 通过后端 job API 提交 Codex 任务。
- 页面顶部提供 `执行模型` 下拉框，支持在 `CLI 默认` 与 Codex CLI 当前可用的 `gpt-5.6-sol`、`gpt-5.6-terra`、`gpt-5.6-luna` 预置模型之间切换；所选项会持久化到本地浏览器状态。
- 当选择 `CLI 默认` 时，提交请求不指定模型，由后端的 Codex CLI 默认配置决定实际执行模型。
- Web AI 编程以非交互 `codex exec` 运行：它不能回答终端审批或输入提示。因此任务明确不会执行 SQLcl/数据库命令、服务启停、Git 发布或推送及其它需要确认的命令，而会报告对应命令、原因和前置条件；这些动作由用户或页面中已有的受控操作完成。
- 页面刷新后恢复最近一次任务。
- 轮询当前 Codex job 状态。
- 运行卡片展示最近 Codex 事件和距上次活动的秒数；连续 60 秒没有新输出时，提示任务可能在等待外部命令、网络、审批或长耗时步骤，并提供终止入口。
- 执行中的任务会展示“终止当前任务”按钮；用户可主动取消当前 job，后端会终止对应 Codex 子进程并释放执行槽位。
- Codex 执行失败后，最近一次失败任务的错误信息、原始输出和错误输出仍会在刷新后保留展示；失败和手工终止卡片都提供“清理结果”按钮，可随时隐藏当前输出，无需提交新任务。
- 新建任务前，前后端都会先尝试恢复并清理残留的运行中 Codex 状态，避免失败后的假性占用长期阻塞下一次提交。
- 离开 AI 编程页时，在全局顶部栏显示执行中/已完成/失败/已终止提示。用户手工终止任务后，结果卡片会以中性的`任务已终止`状态展示，不会误报为执行失败。
- 任务卡片会记录并展示本次运行实际使用的模型名称，便于区分“沿用默认模型”与“显式指定模型”。
- 任务完成后可归档精简记录；所有已结束任务均可仅清理当前任务的内容展示，不会创建可信知识归档。
- 通过后端 API 触发 GitHub 同步，并保留最近一次同步日志尾部。
- `发布并打 Tag` 会读取 Changelog 最近的已发布版本并默认建议下一个补丁版本；用户可修改版本号，但必须在确认弹窗中精确输入 `ok` 才会调用受控后端接口。接口仅以 `bash scripts/commit-to-github.sh --version <版本号>` 运行现有发布流程，完成 Changelog 归档、提交、推送与 `v<版本号>` Tag 推送。
- 右侧新增 `项目变更日志` 区域，以 Markdown 形式只读展示当前项目的 `CHANGELOG.md`；支持手动刷新，GitHub 代码同步成功后会自动刷新，便于同步后直接查看最新变更。
- UI 中存在服务重启相关控件，但项目规则要求涉及真实进程状态的操作由用户手工执行。
- 服务重启需在确认文本框中准确输入小写 `restart` 才会启用确认按钮。
- `代码与服务 > 服务重启` 中的 amber 警示提示在浅色主题下使用更高对比度文字，确保 `scripts/restart-all.sh` 及“前后端会短暂不可用”说明仍清晰可读。

## 分页说明

大多数列表页面使用服务端分页:

- 前端发送 `limit` 和 `offset`。
- 后端响应包含 `items` 和 `total`。
- 前端本地计算当前范围和总页数。

总览页面不同:

- 它是紧凑 Dashboard。
- 每个模块只拉取第一段数据。
- 当前没有分页控件。
- 给总览某个模块增加分页不只是改数字：需要增加该模块的页码状态、计算 `offset`、渲染分页控件，并决定点击卡片跳转后是否保留总览页码状态。

## 搜索、筛选与排序

搜索输入防抖:

- 大多数列表页会先对搜索文本做防抖，再触发加载。
- 搜索条件变化时，页码通常重置为 1。
- 当前记录、待办事项、英语素材、博客工厂和历史查询的筛选清空入口使用同一套紧凑图标按钮样式；横向筛选条内保持控件高度对齐，侧栏筛选区保持全宽按钮。
- 上述模块的 `清空筛选条件` 统一表示“移除当前筛选约束”：用户筛选默认恢复到 `全部可见用户` / `全部用户`，而不是回到当前登录用户；只有单用户可见范围会继续保持该唯一用户。

本地保存的 UI 状态:

- 当前视图、筛选条件、页码、选中 ID、草稿、已选 Skills、AI 回答、AI 编程模型选择、Codex 消息都会持久化到 localStorage。
- AI 问数回答仅在符合当前响应结构时恢复；界面状态版本升级时不会恢复旧版本回答，避免 PWA 使用过期字段渲染而中断页面。
- 侧边栏展开态、移动端导航显隐状态、主题模式也会一起持久化。
- 存储 key：`trustedKnowledge.uiState.v2`。
- 信息录入、知识加工、博客工厂、待办事项和英语素材的用户筛选也在这个 key 内一起保存。

API 缓存:

- API 封装缓存使用 `trustedKnowledge.apiCache.v1:`。
- 总览和列表页优先读取缓存；有缓存时不会自动在线刷新，用户主动刷新或完成本机写入操作后才会更新。个人机密列表缓存只保留 15 分钟，且仅包含后端返回的脱敏摘要。

排序字段:

- 博客工厂：`copied_at`, `id`, `knowledge_id`, `factory_status`。
- 当前记录：`id`, `type`, `week`, `day`, `username`, `learn_level`。
- 历史查询：`history_date`, `id`, `type`, `username`, `learn_level`。
- 英语素材：`id`, `sequence_no`, `category`, `base_expression`, `title`, `flag`。

## 维护规则

以下情况需要更新本文档:

- `FUNCTION_NAV_ITEMS`、页面名称、页面顺序或页面标题变化。
- 任一页面的列布局、面板职责或移动端行为变化。
- 列表每页数量、总览卡片数量，或某个模块是否分页发生变化。
- 搜索、筛选、排序行为变化。
- 新增纯前端控件、复制模式、弹窗、抽屉或详情面板。
- 用户可见状态文案或状态流转变化。

如果后续前端继续扩大，建议把展示配置从 `App.tsx` 抽到一个小配置模块，例如 `frontend/src/uiConfig.ts`。这样手工改展示数量或默认行为会比直接编辑大型 `App.tsx` 更稳。
# Agent 范围的 Skill 选择

AI 功能中的 Skill 选择器必须传入当前业务 Agent，并请求 `callable` 范围。选择器仅加载该 Agent 已关联且当前用户有调用权限的已启用 Skill：包括自己的 Skill，以及其他用户已分享的关联 Skill；自动选中管理员配置的默认项，不再提供“全部 Skill”开关；不同 AI 问数业务域分别使用自己的 Agent。

能力管理使用主从工作台：左侧以 `Agent / Skill` 切换选择对象，右侧仅展示所选对象的详情。Agent 模式左栏使用紧凑的单行 Agent 导航，右侧保留 Agent 标签栏、模块说明、实时关系图与关联配置；Skill 模式左栏同样使用紧凑单行导航。两种模式都可在非输入控件编辑状态下通过上下方向键切换当前项；Skill 切换会同步加载右侧详情。新建与上传 Skill 操作只在 Skill 模式显示。Skill 模式保留元信息与文件编辑。
